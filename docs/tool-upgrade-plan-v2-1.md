# 酿酒致富方案 V2.1 补充：工具等级、劳动效率与升级排程

版本日期：2026-10-13。本文补充 [酿酒致富方案 V2](wine-profit-plan-v2.md)，将工具升级从零散的成本提示提升为生产依赖和明确投资候选。涉及工具等级、升级资金和停工安排时，以本补充为准；原生获取、社区中心、无需外部模型 API、人工接管优先等边界不变。

**状态：策略与待实施规范，不是控制器部署记录。** 原方案没有提供四类工具的实际等级、附魔或升级中状态；不能据此断言玩家仍在使用初始工具，也不能宣称控制器已经会蓄力操作。引用的秋16日数据仍是北京时间2026-10-13 11:48的历史快照，执行前必须重读。[R1][R2]

## 1. 为什么工具是主线，而不是有余钱才升级

镐决定取得金属的击打成本，斧头决定自采木材成本，水壶决定手工农务占用，锄头决定扩田和集中播种的吞吐。它们会影响何时能完成下一次升级、灌溉、酒桶制作和收款，而不只是操作手感。[S1–S5]

应区分三件事：工具材质影响破坏能力或作用范围；相关技能熟练度影响单次体力消耗；执行器是否会使用工具能力决定这些优势能否兑现。高级镐、斧头不是所有单次动作都更省体力，而是通常以更少的击打完成任务；水壶蓄力范围扩大时单次耗能会增加，不能把一次浇5格当成与浇1格完全同耗能。[S6]

**投资目标：减少下一笔可靠回款的等待，同时不牺牲安全、季节窗口和必要周转。** 不要求所有工具先升满才开酒线，也不允许因无限扩桶或补种，让已经证明有效的工具投资长期拿不到资金。

## 2. 升级成本和基础效果

以下为未修改的常规铁匠四类主工具升级费用，不包括购买矿石、煤、补给、旅行和停工机会成本。工具必须逐级升级，不能从初始直接跳到金或铱。[S1]

| 目标等级 | 从上一级升到该级的金币 | 本次材料 | 从初始升至该级累计金币 |
| --- | ---: | --- | ---: |
| 铜 | 2,000g | 5铜锭 | 2,000g |
| 钢 | 5,000g | 5铁锭 | 7,000g |
| 金 | 10,000g | 5金锭 | 17,000g |
| 铱 | 25,000g | 5铱锭 | 42,000g |

累计材料必须包括各前置等级。例如初始升金镐需累计5铜锭、5铁锭、5金锭和17,000g，而不是只有5金锭与10,000g。已有等级直接从真实状态扣除。[S1]

### 2.1 镐：按主要作业矿段制定目标

铜镐可将普通矿井1–39层通常岩石压到1击；40–79层通常岩石由铜镐2击降为钢镐1击；金镐可1击破开80–120层通常岩石。铜矿节点初始镐3击、铜镐2击、钢镐1击。节点种类不同，不能把通常岩石的击打数套给所有矿点。[S2]

建议目标：浅层拓矿优先评估铜；持续自采铁矿时把钢列入近期排程；持续在80层以后取金时评估金。**这些是效率目标，不是进入矿层的硬性游戏门槛。** 可以使用当前合法工具先到达下一矿段、取得升级材料，避免“有钢镐才能去取铁，而没铁不能升级”的循环等待。

铱镐面向更后期的大量自采与适用矿区，不作为首批酒桶或120桶的必需条件。换好镐也不能替代武器、生命、补给和回程安全检查。

### 2.2 斧头：在大规模自采之前升级

常规无附魔、完整成熟普通树，砍倒树干再清掉残留小树桩的击打数如下。[S3]

| 斧头 | 树干 | 小树桩 | 合计 | 相对初始减少的击打 |
| --- | ---: | ---: | ---: | ---: |
| 初始 | 10 | 5 | 15 | — |
| 铜 | 8 | 4 | 12 | 20% |
| 钢 | 6 | 3 | 9 | 40% |
| 金 | 4 | 2 | 6 | 60% |
| 铱 | 2 | 1 | 3 | 80% |

这是击打数量改善，不是包含移动、掉落拾取、找树和补种在内的总吞吐提升保证。铜斧可处理大树桩，钢斧可处理大原木并打开秘密森林入口；有具体解锁任务时，可以提高钢斧优先级。[S3]

酒桶本体500个需15,000木材，额外建筑和设备另计。[R1] 若主要自采，应在成批采木前评估钢斧，随后根据后续采伐量升级金或铱。若现金流已经足以使原生购木更划算，则不为“满级装备”强行升级。保护树脂生产区、挂采集器橡树和批准保留的树木。

### 2.3 水壶与锄头：范围优势必须由执行器兑现

两类工具的最大普通蓄力范围依次为：初始1格、铜直线3格、钢直线5格、金3×3共9格、铱3×6共18格。必须使用原生蓄力再释放，简单单格点击不会自动扩大覆盖。[S4][S5]

水壶升级还增加储水容量，但不能只凭装备等级就预测批量浇水节省。锄头应在批准的大面积开田或集中播种前评估；已经建立的多年生作物单元不应每天被重复开垦。

作为体力校验示例，在耕种5级、无额外熟练度或附魔、71个需浇水格理想可分组时：初始单格约71×1.5=106.5体力；铜壶23次3格加2次单格约23×3.5+2×1.5=83.5；钢壶14次5格加1次单格约14×5.5+1.5=78.5。这是理想分组算例，不是旧农田的实测：地块缺口、朝向、设备、蓄力耗时、补水和走位会改变实际收益。[S6]

## 3. 酿酒路线中的分阶段工具策略

以下是默认投资候选，不是固定的装备硬门槛；先读取实际等级，已达标则跳过。所有阶段都允许在有原料和合法设备时先生产、先回款。

| 生产阶段与劳动 | 镐 | 斧头 | 水壶 | 锄头 |
| --- | --- | --- | --- | --- |
| 浅矿、首笔加工回款前 | 铜列为优先候选 | 有明确采伐或大树桩需求才排铜 | 手浇持续阻塞其他工作时评估铜 | 原级可继续使用 |
| 铁矿稳定、逐步装洒水器、1–30桶 | 持续取铁时优先钢 | 即将成批自采木时向钢推进 | 铜或钢与洒水器比较；灌溉接近完成则延后 | 下一次扩田前才评估铜/钢 |
| 金矿及30–120桶扩产 | 持续取金时评估金 | 按未来采伐量评估钢→金 | 不用升金壶替代可行的稳定灌溉 | 大片开田前评估钢/金 |
| 120–500桶或更高 | 自采收益充分时金→铱 | 自采收益充分时金→铱 | 自动灌溉后通常不再是主要投资 | 集中建设前按地块量评估高阶范围 |

后期大面积收获还可评估铱镰刀，它由耕种精通奖励取得，可以收获所有作物；不是交5铱锭到铁匠就能升级获得。它不应成为首批酿酒的前置条件。[S7] 背包容量、武器和交通另列效率检查，不能混同于四类主工具的材质等级。

## 4. 针对秋16日旧快照的第一步

旧快照为1,428g、71株作物、矿井8层、木材1,448、31铜矿、1铜锭、12煤、无铁料与洒水器。[R1] 它没有真实工具等级，以下只是“若仍为初始工具且这些资源仍在”的条件排程：

1. 首先核对工具、库存、升级订单、天气、当前农务和下一次可靠回款；保护本季必要献祭与收成。
2. 默认把铜镐列入第一批投资候选。已有1铜锭时，再炼4锭需要20铜矿和4煤；前提是已有可用熔炉、资源未被更紧迫用途预留。仅升级费距1,428g还差572g，而且升级后仍需保留必要周转。不能把“凑够2,000g”理解为可以花到0g。[S1][S8]
3. 比较铜壶与铜镐的边际收益：若每天手浇已使矿井任务无法有效开展、蓄力功能已验证、洒水器短期不能到位，而且有安全送修窗口，可以先升铜壶。若很快能覆盖主要田块，则保留资金用于镐或灌溉。
4. 铜镐送修期间照料作物、收获出货、处理已有机器、采木或办理不需镐的献祭事项；领取后推进下一电梯检查点。
5. 取得铁料后，将钢镐与首批洒水器、可立即回款的酒桶放在同一资金评审中；按未来作业量决定先后，而不是所有铁锭都直接锁给酒桶。
6. 当前1,448木材若仍可用，对首批酒桶并非最紧迫缺口，因此钢斧通常晚于第一步金属投资；但在大量补木前应重新评估，而不是等15,000木材全部用初始斧头采完才升级。

这不是固定的游戏日承诺。实际工具已升级、作物改变、铁料已有或灌溉覆盖提高后，必须重算。

## 5. 投资规则：不能只写“有余钱再升”

工具、灌溉、解锁与酒桶共用一个投资队列。计算升级时应估计：

`有效升级成本 = 本次金币 + 材料机会成本 + 送取路程成本 + 无工具期间净损失`

`预期收益 = 未来实际要做的任务量 × 单任务可实现的节省 + 必要障碍解锁价值`

替代工作能利用送修期间的时间，但不能同时算作采矿与农务的双份角色产出。材料即使来自自采也有机会成本；不能只按矿锭出售价格衡量对灌溉或即将回款酒桶的影响。

采用未来14/28游戏日滚动窗口进行比较，记录“升级后第一笔新增回款预计提前多少、哪些投资被推迟、保守情景下能否维持经营”。窗口是规划参数，不是保证回本期。没有足够观测时降低预测置信度、先做最小有效升级，不捏造金币/现实小时效率。

一旦工具升级被批准，就明确预留其金币、矿锭与领取窗口。其他补种、采集器或扩桶任务不得自动挪用；需要变更时输出原因并重新排程。若所有工具都长期处于“没有余钱”，应报告投资饥饿，而不是视为正常经营。

## 6. 铁匠排程：两夜升级，不等于停工两个完整白天

常规升级需经过两夜，送交D日的工具在D+2日准备好；还必须等铁匠实际可访问才能领取。升级逐级办理。规划器按串行队列处理本玩家的铁匠订单；已有订单时不再重复提交。[S1][S4]

镐、斧头、锄头可以在送出当天先完成必要工作，之后切换到其他任务；取回当天及时恢复适用任务。节日、社区中心修复后的周五等会影响领取，必须读当前营业状态，不能假设D+2清晨工具已经在背包。[S1][S4]

**水壶正常无漏浇窗口：** D日预报D+1室外降雨，先完成D日所有必要浇水再送修；D+1由雨覆盖室外；D+2能够实际领取，取回后完成当天浇水。[S4]

雨不覆盖温室或室内花盆；若其未有可靠灌溉，单靠雨日窗口仍不安全。也不能在“今天下雨”时不检查明日就交水壶。季末、冬天、全洒水器覆盖可作为其他窗口，但必须逐块核实跨季作物、冬季作物、新种地块和室内作物是否仍需水。[S4]

少浇一次通常造成未成熟作物停长，而不是立即死亡；但延迟可能错过最后收成或献祭日期。不可把“不会马上死”作为自动漏浇理由。[S4]

## 7. 控制器必须具备的工具能力与状态

下列为建议的规范化字段与状态，不代表现有Together已实现：

| 字段组 | 必须读取或记录 |
| --- | --- |
| 实际工具 | 工具类型、真实等级、附魔、所在位置、可否使用；缺失记unknown |
| 人物状态 | 对应技能/有效熟练度、体力、生命、负重与回程时间 |
| 范围操作 | 是否已验证蓄力、当前可用范围、面向、可达起点、实际受影响格 |
| 送修订单 | 目标工具/等级、提交日、已扣款材料、预计完成日、最早可领取日、真实订单状态 |
| 任务效能 | 同类石头/树木的击打次数、单位材料体力与用时、浇水/开田范围命中率 |

建议订单状态为：`planned → reserved → submitted → processing → ready_pending_access → collected → validated`。工具在合法订单中时，不把背包缺失认定为故障，不生成替代工具，不不断重启。每次恢复先核对金币、矿锭、订单与背包，防止重复交付或重复扣账。

水壶和锄头必须规划朝向、合法站位与蓄力范围，按原生动作释放，再逐格核对浇水或耕地结果；边缘、不规则缺口允许退回小范围。严禁为了满足理论覆盖而破坏作物、地板、设备或通路。

只支持单格动作时，不能把铜/钢/金/铱范围加成计入时间和体力预测。先补充并验证原生蓄力能力，或按仍然可兑现的容量等有限收益评估升级；不能直接写入土地状态模拟多格效果。镐和斧头不按固定击打次数盲敲，必须观察对象是否已移除，以免升级后多打、误伤后方物体。

人工接管会暂停整个提交、领取、移动与实机验证流程。本文和PR更新都不授予恢复游戏的权限。

## 8. 必须补充的验收用例

以下均为待执行测试，未声称在本地通过。

| 场景 | 预期 |
| --- | --- |
| 未采到实际工具等级 | 保持unknown，不假设初始，也不计算已升级收益 |
| 已有钢镐 | 跳过初始和铜升级，不重复预算或送修 |
| 现金2,000g但还需种子/食物储备 | 不把现金花至0；给出缺口与下一次重评时间 |
| 铜矿被另一采购/建设预留 | 不重复承诺同一资源 |
| 工具在铁匠加工中 | 切换合法替代工作；不当故障修复 |
| 提交后断线、重载或玩家接管 | 先核对原生订单，不重复提交；人工暂停不被覆盖 |
| D+2节日关门或其他不可访问 | 延后最早领取日，水壶送修前已覆盖新增无工具日 |
| 预报明日雨但有未灌溉温室作物 | 不把雨日窗口判为全场安全 |
| 初始/铜/钢壶、规则田与缺口田 | 实际格数、耗水、体力分别验证；不因等级自动假定多格成功 |
| 铜/钢镐对相同矿段同种对象 | 比较击打和净任务耗时；不把技能、食物、矿点密度差异归因给材质 |
| 斧头升级后的同类型树木 | 正确停止击打、收集掉落、不破坏受保护橡树 |
| 升级后的经营效果 | 跟踪实际采集、农务耗时和回款变化，而不只检查背包工具名称 |
