# 酿酒致富方案 V2：现金流优先、瓶颈驱动、远古水果长期化

版本日期：2026-10-13。性质：**策略审查与待实施升级建议，不代表已部署控制器、已恢复游戏或已完成实机验证。**

审查基线：`895525e01a0204a186be19cc4bb7d5c2a4496df6` 的 [原方案](current-plan.md) 和 README。原快照为北京时间 2026-10-13 11:48、游戏第1年秋16日；不能把这个快照当作此刻的实时存档。仓库目前保存方案与图表，未包含文档所引用的本地 Together 定制源码、真实存档和运行日志。因此本文可以核查路线与数值，不能确认本地分支是否已实现，也未复跑原文所称的805项检查。

## 1. 总体结论与不变边界

原方案方向合理：本地执行、社区中心路线、原生获取资源、分批扩产、人工接管优先，以及把真实销售和未来供给纳入验收，均应保留。它已经认识到温室不够支撑500桶，也已经指出冬季缓冲需求；这些不是本次新发现。

但原方案更像“安全地逐步建成500桶”，还不是“尽早靠酿酒滚出资金”。主要缺口是：季节解锁审计不够具体；配方等级与生产前置条件没有完整展开；缺少现金流和加工机会成本比较；远古扩繁、次年重播和跨季库存没有统一扣账；500桶验收仍缺连续经营指标。

升级目标为：**先实现最早可行的酿酒回款，再把回款投入当前最限制收益的环节，最后形成以远古水果为核心的全年稳定产线。500桶是产能检查点，不是财富本身。**

以下原边界不变：无需外部模型API；不启用AgentLab或Computer Use；不加入Joja；不改存档创造物资、金币、经验、体力、时间和解锁；不擅卖工具升级材料；保留原生品质、容量、通路和安全规则；人工接管后的暂停不得由本提案覆盖。本文也不默认引入自动收料类新模组。

### 2.2 职业是必查项

检查实际耕种5级选择与10级分支：目标为 Tiller（农耕人）→Artisan（工匠）。不能因等级达到而默认职业正确。工匠对符合条件的加工品增加40%售价，属于本线的重要收益开关。[S2]

没有工匠时，500瓶普通远古果酒仅售825,000g，比有工匠少330,000g/轮。已有错误职业时，另核实原生转职条件、费用和回收期，不通过修改存档纠正。

## 4. 第一优先级：献祭、成熟窗口和季节审计

### 4.1 先采样，后规划

下一次获得明确执行授权后，先读取当前游戏版本、日期、农场类型、献祭类型（标准或混合）、职业、全部箱子与背包、已领取奖励、各作物播种日/生长阶段/浇水状态、矿井电梯层、工具状态、种子配方和机器状态。

采样缺失字段应记为 `unknown`，不能把未知当作零、已完成或正常。任何以秋16日为起点的以下例子，在真实日期改变后必须重算。

### 4.2 温室不是一句“完成社区中心”

温室只需完成茶水间（Pantry）全部收集包，不需要先完成整个社区中心；姜岛属于更后面的独立解锁链。标准品质作物包在5金星防风草、5金星甜瓜、5金星南瓜、5金星玉米中选三组。[S3][S4]

必须检查：春、夏作物是否已经交齐；品质包已完成哪几组；当前还有哪些金星库存；动物产品和工匠物品分别差什么；洞穴选择及已有果树能否提供所需物品。

**若金星防风草和金星甜瓜两组都没有完成且没有库存，仅靠秋季南瓜、玉米只能完成两组，不能把今年温室当作有保证的里程碑。** 旅行货车不卖带星品质物品，不能把随机采购当成品质包的可靠补救。[S3]

对每个缺项生成：`所需数量/最低品质/已交数量/已保留数量/合法来源/最早取得日/最后可播日/置信度/失败后替代任务`。标准与混合收集包必须从实际状态区分，不能用标准清单强行覆盖。

优先保护最后季节窗口里的献祭物品和金星作物；不为了酿酒或售卖误耗。普通品质缺项可顺路检查旅行货车，但不反复读档刷库存，也不无限等待随机出现。

### 4.3 35株南瓜的实际意义

南瓜正常生长13天，每株收获给31耕种经验，普通品质售价320g。[S5] 若秋7日播种、每日有效浇水且没有改变生长期，首熟约为秋20日；以真实作物状态为准。

按旧快照、不计其他收获：

- 35×31=1085经验；2634+1085=3719。可越过6级3300，但距离8级6900仍差3181。
- 全部按普通品质、无职业、不留存的销售基准为35×320=11,200g；真实可售量须先扣献祭、其他保留与可能损失。
- 秋20日收获后，未加速的新南瓜赶不上秋28日。小白菜正常4天、14经验，可在预算、浇水和商店允许时考虑秋20→24→28的两轮；不是不分条件地继续购买长周期种子。[S6]

种植计划必须按“收获能否在截止日之前发生”检查，并分别预测到6/8/9/10级的日期。多产作物的额外果实数量不等于成倍增加耕种经验，经验与数量分开计算。[S2]

### 4.4 若今年温室无法稳定取得

不盲等，也不把未成熟的远古种子种在秋末室外。转为：保全本季献祭窗口与收入；冬季主攻矿井、金属、灌溉、工具、树脂和来春种子；保留可酿酒的真实原料。

若实测版本支持1.6机制且有合法种源，冬季可把霜瓜及冬季种子作物作为经验/现金流补充。霜瓜正常8天、12耕种经验；野生种子作物在1.6可给3耕种经验，但不能当成高效、无限种源的耕种冲级方案。[S2][S7]

## 5. 当前资源分配：先解除劳动与金属瓶颈

### 5.1 挖矿分“开路”与“采集”

旧快照最深8层，说明稳定铁矿和金矿来源都未建立。[R1] 普通矿井铁矿主要阶段为40层之后，金矿为80层之后；电梯检查点应成为阶段成果。[S8]

设两种明确任务：

- `unlock_depth`：安全到达下一电梯检查点，优先原生楼梯与必要战斗，减少为普通石头或低价值支线绕路。
- `farm_materials`：已到合适矿段后，根据真实缺口采铜/铁/煤/金；不重复把浅层采矿误当成解锁进展。

若镐仍未升级，比较铜镐的2,000g和5铜锭投资与实际节省的击打、体力和时间。升级期间要有可执行替代工作，不把工具不在身上误判为故障。铁匠升级与采购按当天真实开放状态执行。[S9]

不降低生命和回程安全线来硬冲深度；补给不足时先领食物或准备任务。危险层解锁必须以战斗能力实测为条件。

### 5.2 灌溉是扩种的前置条件

优质洒水器需耕种6级、1铁锭、1金锭、1精炼石英，覆盖周围8格。取得奖励成品不需要会制作，因此也应检查夏季作物包等已可领取的奖励。[S10]

建议从可负担的2–4个单元开始，再扩到覆盖主田的数量。纯9×9方阵可按9个3×3单元布局，理论为9台、72作物格；稻草人、围栏、通路或不可放置地形会再减少实际格数。保护已有活作物，利用收获空格渐进迁移，不能为了整齐铲掉正在回款的作物。

初期进金矿层太慢时，比较奖励设备、少量购买金矿自炼、暂用少量基础洒水器和继续手浇的成本。不要因暂时缺金就把所有扩种收益都放弃，也不要为了完整自动灌溉一次花光现金。海滩等农场的沙地限制必须由真实地块判定。

### 5.3 树脂要提前准备，但不能挤掉更紧迫的投资

标准采集器成本40木材、2铜锭；橡树树脂正常每7夜产1份，冬季仍生产。[S11] 旧快照已8树脂、6台采集器，在全为可达橡树采集器、及时收取且无损失的假设下，未来28天约新增24树脂。

这意味着：若耕种8级或铁矿仍要较长时间，现有采集器可能已能覆盖10桶乃至30桶的树脂需求；是否补到8台，应看实际成熟时点，而不是为了完成数字任务立即挤占铜镐或熔炼预算。反之，明确能很快消化几十桶材料时，应提前扩采集器，不能等树脂断供才做。

建议按“未来28天计划新增酒桶需要的树脂−现存可用树脂−已安装采集器按日期预计产量”计算缺口。扩至16/24/48台是可选结果，不是固定顺序。树脂累计覆盖本阶段扩桶目标后停止继续扩大采集器，除非新的扩产计划已批准。

木材1448对首批酒桶并非最明显短板，不再把清空全农场石头和树木作为酒线前置任务。保护橡树生产区与树种，清理只围绕种植、建筑、物流、资源缺口和必要通路进行。

### 5.4 现金储备与材料采购

用下一次可靠回款前的必要购种、食物、任务费用、已排期工具升级和献祭采购计算动态储备。建议每次采购前输出“买后剩余现金、已保留支出、预计回款日、最坏情况下是否断供”。没有可靠预测时缩小采购批次。

金币增长后，允许比较原生购买矿、煤、木材与自行采集的机会成本：购买若能提前一批高价值酒的回款，可能比长期人工采集更划算。铁匠矿煤价格在第2年上涨，不能沿用第1年成本模型。[S9] 但不为“囤便宜材料”提前花掉种子、补给和关键解锁预算。

## 6. 双线生产：现在赚钱与长期扩繁并行

### 6.1 现金流线

就近可得原料→少量酿酒桶→实际取酒/出货/到账→再投资。取得任何合法奖励酒桶即可做1桶闭环试验；可制作后也不必等10桶材料全部到位。标准工匠收集包奖励1桶，但只有顺路可完成时才用这条捷径，不为绕开8级而另开昂贵支线。[S12]

季节水果可过渡；南瓜汁、啤酒等可以帮助筹款，但财务记录要按产品分类，不能计作远古果酒验收。已有腌菜瓶可以利用；是否新建更多，须比较其材料与对酒线的延误，不能自动无限铺开。

原料选择看**每桶占用时间的加工增值**以及资金回收日期，而不是“哪个售价高”或“有水果就全部压酒”。

`加工增值效率=(加工后实际售价−原料直接出售价值−额外可变成本)/占用游戏时间`

低品质通常优先加工；同种原料品质并不会直接提高普通果酒售价。高品质原料的直售价更高，应比较保留、直售和加工机会成本。[S12][S13] 有高价值原料即将到来时，不应把所有桶先塞进低价值长周期产品。

如果卖掉部分普通收成能立即解锁关键工具或灌溉，允许先直售；不为了未来酿酒把整个农场现金锁在箱子里。

### 6.2 杨桃作为有条件的桥接原料

杨桃种子在沙漠绿洲正常400g、基础13天成熟；普通杨桃酒2250g，有工匠3150g。[S14][S15] 因种子可购买，适合在沙漠可达、季节或温室允许、手头有种子预算而远古尚未扩满时，按可照料面积和桶容量小批种植。

杨桃不是无条件替换远古：每轮要重买种子、播种和等待，种子费与周转时间不可忽略。举例，3150−400=2750g只是扣种子后的单株单轮收入，仍未扣其他成本；基础13天产一果，也不能按“1株每周喂1桶”估算。

空温室可以分区：已有远古种子立即播种；尚无远古种子的空区种能在需要腾地前收完的高价值过渡作物。不能为等待凑齐全套远古种子而长期留空，也不能用长期占地作物堵住扩繁。

### 6.3 啤酒花不是必走捷径

啤酒花成熟后每日收获，可酿淡色艾尔，但棚架不可穿行，装卸频率高。[S16] 在自动化可靠、夏季或全年种植地可用、桶较多而土地较少时才做独立评估。当前目标仍是规模化果酒；不为理论地块收益再引入一条高频、尚未验证的复杂主线。

### 6.4 远古育种线

寻找文物远古种子时，可与铜矿段清虫、顺路挖文物点结合。首次文物捐博物馆可获可播种种子与配方；这是与耕种8级独立的工作，不应等酒桶做完才开始。[S17]

种子生产器常规配方是耕种9级；已有染料收集包奖励等合法成品也可使用，但不假定已经拥有。常规产出为97.51%概率产生1–3同类种子，另有混合种子和远古种子的随机结果；不能把每次产种固定写成2。[S18]

远古植物通常首熟28天，此后每7天产果。[S1] 必须逐批记录播种、首熟、后续收获与真实产种。新种子还要再走一遍首熟期，所以扩繁不是每周全部植株立即翻倍。生长加速条件只有实际获得且使用后才纳入日程，并且只影响首熟，不把7日再生周期同步缩短。

每份果实只分配给一种用途：献祭/任务、扩繁、下一春重播、酿酒或出售。扩繁所需的目标是“近期真正能灌溉和种下的地块+批准的下一阶段种子储备”，不是无限期把所有果实都制种。达到种子目标后，更多果实转入现金流线。

## 7. 从108/116周产到500周产的供料模型

### 7.1 先把温室做成独立盈利单元

标准温室有120耕地格。16台优质洒水器布局占12格，可种108株；6台铱洒水器布局占4格，可种116株。更高级布置可另评估，但不得提前把108写成116。[S4]

对应先做约108或116份/周的成熟远古供料单元。保留原120桶节点时，应明确其中的余量桶用什么供料、作为备用还是主动闲置；不能把120台设备都记成远古水果满产。

### 7.2 稳态扩桶条件

定义：`G` 为全年成熟远古株数；`O` 为当季室外成熟株数；`S(t)`为按日期可用水果库存；`B(t)`为已经保留给扩繁、重播和献祭的水果；`L(t)`为计划装料量。

按每7日一轮的简化计划，全年稳态大体需要每周净可用水果量不小于实际装料桶数。精确排程必须对每次装料验证：

`可用库存(本轮)=上轮结余+装料前实际可得收获−新保留量−本轮装料量 >= 0`

桶内正在发酵的水果已被消耗，不能再次计作可供下一轮的水果；成酒不是果源；未播种、未解锁土地和概率掉落不能算“已落实供给”。

每次扩建同时满足：配方或奖励设备合法；材料扣除保留后够用；设备位置可达；现在有一轮可装原料；未来至少两轮按成熟日期不缺料；采购后现金储备不破；任务吞吐足够。近28日预测必须检查每个装料时点，而不只比较月底累计总量。

供料不足时降低建桶优先级；原料堆积且采购能尽快回本时提高建桶优先级。允许小量前置设备等候即将确定的收获，但必须有明确日期和闲置成本，而非无上限堆空桶。

### 7.3 姜岛：建议优先比较的全年扩张方向

若原生解锁成本与等待时间合理，采用“温室+姜岛全年远古种植”支撑500桶，可减少冬季死亡、次春首熟和年度重播库存管理。姜岛作物不受季节限制，但到岛、开放农田、灌溉、运输和自动化都要真实解锁并验证。[S19]

例如116温室成熟株+384姜岛成熟株=500株，在每周一果且全部用于酿酒的理想稳态下可配500桶；若还需继续育种、补种或防损，应增配株数或降低承诺周产，而不是把同一果实重复用于扩繁和满载。

姜岛不是当前阶段立即可用的资源，也不应为了上岛停止更早可行的季节酒收入。选择比较的是“最早达到稳定目标收入的路线”，而不是预设所有存档都必须先上岛。

### 7.4 无姜岛时：修正室外年产示例

沿用原方案假设：全年16轮、每轮500份；温室116株全年已成熟，每株16果；室外春1播种、无加速、及时收获，每株当年8果。于是年酿酒需求8000份，温室1856份，差6144份，忽略其他用途时室外需要768株。这一算术正确，但不包含来年重播与损耗。

若下年室外种子完全靠当年远古水果制种，按[S18]的概率，单果期望远古种子数约为 `0.9751×2+0.005×1=1.9552`。仅为重播就需要约 `O/1.9552` 份水果。因此理想期望下要满足：

`116×16 + O×8 − O/1.9552 >= 8000`

解得 `O >= 821`。这只是期望值下的规划下界，不是821株必然足够：实际随机产种、种植日期、漏水、收获延迟、扩繁和损失会改变结果。若已提前储备下一春全部种子，当前年度可不重复扣这一项，但必须在跨年度账本说明种子来源。

同时，在约8个周装料点没有室外新果而温室持续供应116份/周的示例中，季节缺口为 `(500−116)×8=3072` 份水果；还须按真实装料相位、下一季首熟日、种子储备和安全余量重算。3072不是任何存档通用的固定库存阈值。

不能只靠“年度总产够了”宣告可运行：建线第一年的期初库存、冬前库存以及次春每个装料日都应非负。

## 9. 本地执行器应增加的能力

以下为设计与实施清单，不宣称源码已有对应类或本次完成实现。

### 9.1 从固定任务轮转改为依赖驱动调度

保留原本地执行器与原生动作；在上层增加阶段、截止日期、资源预留和供料预测。每个任务带：前置条件、所需资源、截止日、完成证据、预计收益/解锁收益、安全返回预算、阻塞原因和下一次可重试条件。

推荐顺序：控制权与安全→不可错过的季节/成熟窗口→已投入资产维护→到期机器与当日关键交易→当前瓶颈任务→有收益的顺路工作。

等待树脂、作物或开店是正常状态，但应有 `wake_at` 或事件触发。不能反复选择“当前无法完成的任务”，也不能在所有高收益任务都被阻塞时无意义来回走动。

### 9.2 单一资源账本

建议增加下列只读/规划字段，并为其定义单位和证据来源：

- `snapshot_at / game_date / control_epoch / active_policy_version`
- `farming_xp / farming_professions / mine_elevator_floor`
- `kegs_installed / kegs_reachable / kegs_running / kegs_ready`
- `fruit_free_now / fruit_reserved_seed / fruit_reserved_bundle / fruit_in_process`
- `harvest_schedule_by_cohort / seed_stock_next_spring`
- `supported_kegs_now / supported_kegs_14d / supported_kegs_year_round`
- `cash_actual / cash_reserved / cash_free / revenue_realized_28d / operating_cashflow_28d`
- `blocked_by / next_unblock_condition / recipe_actually_known`

预留账以真实物品数量、品质和位置为底层；每一份资源最多分配一次。计划工具升级的矿料、洒水器金属、酒桶金属和制种煤不能重复承诺。规划数量与原生交易完成数量必须分开。

### 9.3 动作闭环与补给

动作至少采用 `计划→前置核验→原生执行→状态差异核验→记录完成`。每次买种、制作、装桶、收酒和出售应检查前后数量与金钱变化；菜单选择失败不能仅凭函数返回就记成功。

发生中断先查真实机器/箱子/钱包，再决定是否重试，避免重复购买或对已装料的桶重复投料。任务批次带唯一ID用于日志关联，不假定游戏本身提供事务。

保留“回仓存全部非工具”的旧约束，随后按新任务领取清单补给。先确认为战斗必需的装备、食物与回程手段都已就位，才允许进入矿井；不能存完食物就空包出矿。

### 9.4 布局与规模吞吐

先验证小模块，复制扩张；每个模块有可达入口、可操作机器、装卸点和箱子容量预算。前期不把昂贵建筑作为开工前置条件；已有安全空间可用时先放桶。以后是否造棚屋应比较成本、占地、原生可达性和装卸时间。

500桶必须测量角色在安全时段内实际能完成多少装卸。必要时把作物与酒桶划为多日错峰批次，按各自原生完成时间工作，而不是让全部作业拥堵在同一天。箱子容量按物品种类、品质、兼容堆叠和物流批次验证，不能只看总件数。

## 10. 监控、人工接管和策略质量

原300秒只读采样适合作为外部审计；生命、体力、时间、菜单、通路和人工输入保护必须留在本地动作/事件级，不能等待下一次五分钟采样才响应。[R1]

把问题分成两类：

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 执行故障 | 菜单未关闭、寻路循环、读写状态不一致 | 保留证据；只做授权内、可验证的恢复；源码变更经离线检查与安全保存后再部署 |
| 经济停滞 | 铁金矿解锁不前、反复补种导致缺钱、树脂过剩却继续制采集器 | 调整计划或上报阻塞，不能把它当成“多重启一次就好” |

建议初始预警窗口为连续3个有相关任务机会的游戏日没有瓶颈进展；这是待调优的策略参数，不是游戏机制，也不能把正常生长等待判为卡死。分别跟踪配方经验、解锁缺项、有效灌溉、关键金属、远古成熟株数和实际到账。

人工控制采用递增的控制版本/授权记录；新接管使旧的恢复许可失效。安装、重启、睡觉保存和继续运行前都要再核对。纯文档更新不构成恢复授权。

对未知故障，保留只读诊断与离线修复路径，不用未经检查的任意代码热修复换取无人值守时长。无法安全保存或状态不一致时停在安全边界，不杀未保存进程。

## 11. 验收：功能、经营、持续供料三张表

### 11.1 功能验收

保留原两轮真实闭环：原生装果→等待真实加工→收酒→出货→次晨对账。果实品种、酒品种、数量和收入一一对应；其他产品收入与远古果酒分账。

### 11.2 经营验收

建议采用连续28游戏日观察窗。成熟稳态500瓶/周的计划为2000瓶/28日；可以将达到计划产量95%作为初始服务目标，但必须同时给出实际数量与原因，不用“达标百分比”掩盖未满产。

跟踪：实际销售、经营净现金流、扩产现金支出、成熟机器等待装卸时间、可避免缺料时间、事故损失与人工接管次数。原生6.25天左右加工与每7天采收产生的计划间隔，不算执行故障。[S12]

### 11.3 持续供料验收

未来每个装料点库存非负；扩繁和重播种子已扣除；至少覆盖下一次季节断档及下一次首熟；所有依赖的土地、灌溉和植物都真实存在。全年稳态只能在全年来源或完整跨季储备被验证后标记。

建议把“达到500桶”后的任务由扩建转为经营，而非自动停产。若旧运行授权规定验收即暂停，必须先由用户明确更新该约定；本提案不自动改变既有停机、恢复或监控许可。

## 12. 实施优先级与回归测试

### 12.1 建议实现顺序

P0：献祭缺项与季节审计、真实快照字段、职业检查、逐作物经验预测。

P1：矿井开路/采集任务分离、食物领取、灌溉依赖、动态现金和资源预留。

P2：1桶闭环、季节原料加工选择、按成熟日计算的扩桶门槛、原生交易对账。

P3：远古分批育种、温室实际格数、跨季与重播库存、全年土地扩张比较。

P4：250/500规模的通路、箱子、错峰装卸、28日经营验收与经济停滞预警。

### 12.2 必须覆盖的回归场景

| 场景 | 预期结果 |
| --- | --- |
| 35南瓜、初始2634经验 | 预计+1085，到3719；不误报8级 |
| 秋20日、无生长加速，试图补种南瓜 | 拒绝不可能在本季收获的种植计划 |
| 品质包只可能完成南瓜和玉米两组 | 报告温室不具备可靠本季完成路径，检查其他来源与下季计划 |
| 耕种6级但没有金锭 | 不把优质洒水器标成可制作；尝试合法替代任务 |
| 只有奖励酒桶、不会配方 | 允许使用已有桶，不允许凭空批量制作 |
| 铜锭已保留给工具升级 | 不再同时计入采集器和酒桶可用材料 |
| 回仓全存后准备下矿 | 重新领取并核验补给，缺补给不出发 |
| 116远古成熟株、500桶、无其他来源 | 最多按净可用果实计划装料，不标为500桶持续供给 |
| 500水果已被投入在制酒 | 可供下一轮的水果库存扣除500，不重复计数 |
| 一批果实全部投入制种 | 这批果实不再计入酒线收入与装料预算 |
| 温室使用优质洒水器布局 | 按实际地块计算，标准优化布局为108而非116 |
| 116温室+768室外，缺下一春种子 | 不把不扣制种消耗的8000份毛产量作为可持续净供给 |
| 500桶、每天装卸吞吐不足 | 缩小批次或错峰，不无限重试同日完成 |
| 买种执行后中断 | 先核对库存和钱，再决定重试，不重复购买 |
| 用户接管发生在准备重启之后 | 旧许可失效，保持暂停 |
| 作物正常未成熟而资金充足 | 等待成熟属于正常，不错误触发重启或失败 |

以上是待实现/待执行测试用例，不是本次已通过的本地回归测试。

## 13. 当前快照下最值得先做的五件事

在新的明确执行授权和实时重采样之后：

1. 审计温室献祭缺项与品质包，保留秋季窗口物品，同时确认耕种职业。
2. 保住35南瓜回款，算清真实到6/8/9/10级的收获日；秋末只补能及时成熟且不会挤占关键资金的作物。
3. 将可用劳动优先用于安全开通铁/金矿段、补给与分批灌溉，避免一直在浅层搬资源。
4. 现有树脂按日期入账，采集器按扩桶缺口增加；远古种源寻找与材料工作同步推进。
5. 有合法酒桶和适合的现有原料就开始第一笔加工，不等温室、远古种满或10桶齐套。

**总体路径：献祭与季节审计 → 本季现金回收/矿井/灌溉 → 小批真实卖酒 → 温室育种与高价值过渡 → 按净供料扩产 → 500瓶/周持续经营与财富增长。**
